# KYROCUT X1 Project Format v1

## Identification

- File extension: .kcx1
- Container: UTF-8 JSON
- Format identifier: kyrocut-project
- Version: 1
- Timebase: rational frames per second
- Canonical clip time: integer frames

## Top-level shape

```json
{
  "format": "kyrocut-project",
  "version": 1,
  "application": "KYROCUT X1",
  "name": "Untitled project",
  "frameRate": { "numerator": 30, "denominator": 1 },
  "resolution": { "width": 1920, "height": 1080 },
  "media": [],
  "tracks": [],
  "playhead": 0
}
```

## Media references

Each media entry has a stable project-local ID, display name, media kind, source metadata and portable locator. The locator is relative to the project asset root or an application-managed asset ID. A project file must not depend on an absolute path from the machine that created it.

The manifest does not embed media bytes. Asset packaging and relinking are separate workflows.

## Tracks

A track has a stable ID, display name, kind, mute and lock state, and an ordered list of clips. Supported v1 kinds are video, audio and graphics. Future schema versions may add adjustment, nested-composition and effect tracks.

## Clips

A clip references a media ID and stores:

- timeline start frame
- source in frame
- duration in frames

The timeline end is start + duration. The source out is source in + duration. Clip duration must be greater than zero. A clip's media ID must resolve to an entry in the project's media table.

## Compatibility and migration

Readers must reject unknown major format versions with a clear error. Minor compatible additions may be ignored only when explicitly marked optional. Migrations must be deterministic, preserve unknown data where possible and never silently discard edit decisions.

## Current implementation note

The first browser editor currently writes second-based clip values in its v1 JSON manifest while the Rust core uses integer frames. Before declaring cross-platform project interchange complete, the web serializer must be migrated to integer-frame clip fields and covered by round-trip tests. This is an explicit compatibility task, not an implicit guarantee.
